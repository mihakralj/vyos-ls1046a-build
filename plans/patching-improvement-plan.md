## 2. New Findings From the Implementation Round

### NF-01 (CRITICAL): Five workstream patches dropped from the build

`a88b006`/`178d6bd` removed `0158` to `0162` from the series ("context-drifted... skip for now to unblock the ENQ-fix build"). These are not peripheral: fqid-resolution-compose, e2-hash-probe, EKFC programming, RCCB-to-FE_ENTER direct dispatch, and the port-arm EKFC fix. The active FE-VM/EKFC workstream is now absent from the shipped kernel, and nothing tracks that fact except a commit message. A skip is a silent functionality subtraction; the 2026-05-11 SFP incident already taught what silently-absent patches cost.

### NF-02 (CRITICAL, root cause): The skipped patches are un-appliable *by construction*

`0158` to `0162` are raw `git diff` output with no mail headers (the `Subject:` probe finds nothing in them; `0163` has one). They were generated by diffing a tree that already contained Layer 2 fixup mutations. Their preimage context therefore includes text that the pristine patch stack never produces, so they can never apply cleanly to a Layer-1-only tree, at any kernel version, with any amount of 3-way. This is the derived-state poison of TA §2.4 materialized: patches born from a mutated tree are stack-incompatible from birth. No refresh of line numbers fixes them; they must be regenerated from a tree whose state is fully described by the stack.

### NF-03 (HIGH): F-084 regressed to a documented silent no-op

`fa2f147` reverted F-084 from `mutate.py` back to bare `sed` because its anchor lives inside skipped `0158`, and `mutate.py`'s hard fail would abort the build. The log line now reads "(sed, silent no-op if 0158 skipped)". The loud-failure mechanism worked exactly as designed, detected a real inconsistency, and the response was to silence the detector instead of fixing the inconsistency. The correct forms were either a series-conditional guard (run F-084 only when `0158` is staged) or folding F-084 into `0158` itself. This is the precedent to kill immediately, before it becomes the house style for every future mutate failure.

### NF-04 (HIGH): `kernel-roundtrip.sh verify` is destructive and false-positive

`cmd_verify` calls `cmd_export` with output aimed at the **real** `$PATCH_DIR`, which begins with `rm -f "$out"/*.patch "$SERIES"`. It then compares the freshly regenerated real directory against a `$tmp` directory that was never populated. Every patch prints `NEW`, the mismatch counter stays 0, and the tool prints `Round-trip identity VERIFIED`. Running `verify` today deletes the curated series file (all 66 metadata comments, section headers, SKIP annotations) and reports success. This must not be run until rewritten.

### NF-05 (HIGH): Export renumbers into the downstream protection glob

`cmd_export` uses plain `format-patch`, producing `0001-*` onward, and regenerates the series as bare filenames. Two consequences: all metadata comments are lost on every export, and exported patches named `0001-*`/`0003-*` collide with the stale-patch cleanup in `ci-setup-kernel.sh`, which deliberately **preserves** `0001-*` and `0003-*` as vyos-build's own patches. A stale exported `0001-*` from a prior run would survive the cleanup and double-apply. Name stability is a downstream-contract requirement, not cosmetics.

### NF-06 (MEDIUM): Series file carries five dangling metadata comments

Where `0158` to `0162` lines were deleted, their `# Upstream-Status... | Risk-Tier...` comment lines remain, orphaned above `0163`. Comment-adjacent metadata has no binding to its patch line; the association broke on the first edit. Confirms trailers-in-commits as the only durable home.

### NF-07 (MEDIUM): The manifest formalizes unaudited debugging archaeology

Active entries include `F_055` ("F-060 v3d MUX context write"), `F_056` ("F-058 MUX/Transition/ENQ AD writes"), and `F_073D` ("Terminal ENQ w0=0x02010000, w3=0"). F-058/F-060 are the diagnosed descriptor-stomping zombies; terminal ENQ belongs to the closed ENQ-as-MISS experiment family. Listing them as active without a disposition audit converts "we forgot to remove it" into "it is policy." The manifest needs a third state beyond active/removed: each active entry gets a disposition (`fold-into: <patch>`, `retire-after: <gate>`, or `permanent-with-justification`).

### NF-08 (LOW): Meta-tooling has its own bugs

`test-fixups.sh` check [1] writes `_fixup_bash_check.sh` to the CWD but runs `bash -n` against `/tmp/_fixup_bash_check.sh` whenever `/tmp` is writable, validating a stale or absent file. `2c23edb` ("git add -A regression, was only adding .gitattributes") shows the same class inside the apply loop edit. The tooling that guards the fixups needs the same one-shot test it applies to them: a CI job that runs `test-fixups.sh` and a dry-run staging pass on every push touching `bin/`.

## 3. Synthesis

Phase 0 achieved its goal: drift is now loud. What the round proved is that loudness without a repair verb produces worse outcomes than silence, because the only available responses to a loud failure are *skip the patch* (NF-01) or *silence the detector* (NF-03). The refresh verb, TA Phases 1 and 2, is no longer an architectural nicety; it is the blocking dependency of the workstream, since five active-development patches are out of the build until a tree exists in which they can be regenerated. The plan below therefore front-loads a Recovery phase that is simultaneously the first real exercise of the canonical branch.

## 4. Corrected Target Model (deltas from TA)

The TA model stands: canonical git branch, one commit per patch, patches as generated export, fixups folded into owning commits. Four corrections from the implementation evidence:

1. **Metadata lives in commit trailers**, never in patch files (breaks `git apply` on raw diffs, NF) and never as series comments (unbound, NF-06). Trailers: `Patch-Name:`, `Upstream-Status:`, `Risk-Tier:`, `Fixups-Folded:`. The exporter regenerates the series file, including human-readable metadata comments, from trailers. Series becomes a pure build artifact.
2. **Name stability via `Patch-Name:` trailer.** The exporter renames `format-patch` output to the trailer value, preserving today's `NNNN-name.patch` identities, keeping the downstream cleanup glob safe (NF-05) and diffs reviewable. New patches get the next free number at export; letter suffixes end.
3. **Non-destructive verify.** `verify` exports to a tempdir only, compares against the working patch dir, exits nonzero on any mismatch, and never touches the real directory. `export` refuses to run with a dirty patch dir unless `--force`.
4. **CI becomes a refresh generator, not just a detector.** The apply loop already commits every patch into the throwaway repo. When a patch lands via 3-way fallback, `git format-patch -1` of that commit **is** the refreshed patch. CI uploads `refreshed-patches/` as a build artifact and annotates a warning per patch. Human action drops from "reconstruct the fix" to "review and commit the artifact."

## 6. Patch-Type Policy ("what kinds of patches we perform")

Every change to kernel behavior must be exactly one of these types. The type is declared in the `Risk-Tier`/`Upstream-Status` trailers and determines its rules.

| Type | Definition | Rules |
|---|---|---|
| T-NEW (Tier A) | adds new files, touches only its own Makefile/Kconfig line | plain patch; near-zero bump risk; preferred form for all new subsystems |
| T-EXPORT (Tier B) | demotes statics, adds `EXPORT_SYMBOL_GPL`, adds accessors to hot files | expressed as Coccinelle semantic patch where feasible; otherwise minimal-context diff; one logical export per patch |
| T-HOTEDIT (Tier C) | modifies upstream logic in `dpaa_eth.c`, `fman_port.c`, `fman_keygen.c`, `sfp.c` | size budget enforced (soft cap 150 changed lines); mandatory human review at every bump; primary upstreaming candidates; every T-HOTEDIT PR states why it cannot be T-NEW or OOT |
| T-BACKPORT | cherry-picked upstream commit | carries `Upstream-Status: Backport <sha>`; lives first in the series; deleted wholesale at the bump that contains it |
| T-SHIM | mutation of vyos-build scripts we do not own (Layer 3) | anchor-verified with hard exit (current discipline); each shim carries an upstreaming note for vyos-build |
| T-CONFIG | Kconfig fragment forcing | config files only, never source mutation |
| T-OOT | out-of-tree module source (`ask.ko` model) | the preferred destination for all new logic; zero patch surface; the standing question for every proposed patch is "why is this not T-OOT" |
| T-FIXUP | post-apply source mutation | **forbidden as steady state.** Transitional only, `mutate.py`-mediated, manifest-listed with disposition, folded or deleted within two integration cycles (rule P5) |

SKIP is not a type. A series SKIP requires a ledger entry (`plans/skip-ledger.md`): reason, owner, expiry date, restore plan. CI fails when a SKIP passes its expiry. NF-01 gets the first five entries retroactively.

### Phase 1: Canonicalize (~1 week)

Branch pushed (separate `ls1046a-kernel` repo or protected branch); CI round-trip identity gate on every PR touching `kernel/common/patches/`; apply loop iterates the series file; fallback counter summary plus refresh-artifact upload (§4.4); `test-fixups.sh` runs in CI on every `bin/` change with a dry-run staging pass.

### Phase 2: Fold the fixup layer (~2 weeks, interleaved with board work)

Ordered by the R6 disposition list, lowest-risk first: each fixup becomes `commit --fixup` on its owning patch-commit, autosquash, export, delete from script and manifest, FE-VM-affecting ones gated on a board `fe_verify` pass. Exit gate: `manifest.json` active count for kernel-C mutations = 0; `mutate.py` deleted; ci-setup-kernel.sh shrinks to config + Layer 3 shims + staging.

### Phase 3: Bump machinery (at the next kernel bump)

Rebase-driven bump with rerere (cache committed), mergiraf enabled per the prepped attributes, every 3-way and mergiraf event logged into a bump record, conflict census per tier feeding the first upstreaming batch (M8), weekly canary extended to rebase the canonical branch onto `linux-6.18.y` HEAD and report conflicts per commit.

### Phase 4: Steady state

Patch-type policy enforced at review; skip ledger empty; §17 static asserts plus KUnit descriptor audit in every build (carried over from TF-2026-07-18-001 Priority 1, still the cheapest tripwire in the whole program).

## 8. Binding Rules (P-series, same force as the R/T/C rules)

```text
P1  No bare sed/regex mutation of kernel C anywhere in the pipeline.
    Transitional mutations go through mutate.py; steady state has none.
P2  Every mutation is count-gated, manifest-listed with a disposition,
    and series-aware: it hard-fails only when its anchor-owning patch
    is staged, and refuses to run when it is not.
P3  No SKIP without a ledger entry (reason, owner, expiry, restore
    plan). CI fails on expired skips. Silencing a detector is never an
    accepted resolution of what it detected.
P4  Drift gets refreshed, not skipped: a 3-way fallback or mutate
    failure files a refresh task; the CI refresh artifact is the
    starting point; resolution lands within one integration cycle.
P5  Fixups are temporary by definition: fold or delete within two
    integration cycles, enforced by manifest disposition dates.
P6  Patch metadata lives in commit trailers only. Patch files and the
    series file are generated artifacts; hand edits to them are
    rejected once Phase 1 lands.
P7  Patch names are stable identities (Patch-Name trailer). Nothing in
    the pipeline may emit patches named into the downstream 0001-*/0003-*
    protection namespace.
P8  Patches are generated only from trees whose state is fully
    described by the stack. Diffing a fixup-mutated tree into a patch
    is the NF-02 poison and is banned.
P9  Meta-tooling changes (apply loop, roundtrip, mutate, test-fixups)
    require test-fixups.sh green plus a dry-run staging build in CI.
P10 Structured/auto merge output (3-way, mergiraf) is never review.
    Tier C resolutions and anything under the mergiraf denylist get
    human eyes; everything gets the compile-time §17 asserts.
```
